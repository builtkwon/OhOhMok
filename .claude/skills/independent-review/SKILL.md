## MUST

- 파일을 만들거나 고치지 않는다. 결과는 보고로만 낸다.
- 완료 보고에 "통과"라고 쓴 명령마다 출력이 있어야 한다. 출력 없는 통과는 필수 수정으로 지적한다.
- 지적은 필수 수정 / 합의 필요 / 선택 개선 중 하나로 분류하고 근거(파일:줄 또는 명령 출력)를 붙인다.
- 테스트 통과만으로 통과 판정하지 않는다. 체크 5항목을 모두 본다.

## 단계

- S1 입력 확인: 요청 원문, 승인 범위, diff, 완료 보고. 빠진 것이 있으면 그것부터 보고한다.
- S2 보고 대조: 보고의 실행 명령·결과와 전달받은 출력을 맞춘다.
- S3 재실행: `npm test`. UI 변경이면 `npm run test:ui`, 방·시계 변경이면 `npm run test:team`(망 없으면 생략 사유).
- S4 체크 5항목:
  - 요청 누락: 요청한 것이 다 들어갔나
  - 무관한 변경: owns 밖 파일, 요청 밖 리팩터
  - 이음새 준수: TODO-CONTRACT 합의 없이 바뀐 메시지·저장 키·CSS 변수·DOM id·전역 함수, ai.js 직접 수정
  - 테스트: 정상·실패·경계값(금수, 시간 초과, 이탈·승계, 옛 데이터)
  - 문서 일치: README·docs가 코드와 맞나
- S5 보고: 지적 목록(분류·근거), 실행한 명령·종료코드, 미검증 범위.
