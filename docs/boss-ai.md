# 보스 AI(JOONSAMA) 측정 기록과 검토 대기 안

## 현재 구성 (`ai.js` `LEVELS.boss`)
- `depth 10, K 12, ms 3500, vcf 16, vctD 6, def: true`
- 순서: 즉시 승리/막기 → (방어) 상대 열린4·3-3·4-4·4-3·6목 자리에 가산점 + 탐색 후보에 강제 포함(최대 8칸) → VCF/VCT로 내 필승·상대 필승 확인(시간의 50%) → 반복 심화 알파베타(3.5초).
- 학습: 판이 끝나면 국면을 0/90/180/270° 네 방향으로 저장(`learn`, `rotKey`). 상 엎기 = AI 1패로 기록.

## 패배 분석에서 알게 된 것 (`tests/analyze-losses.js`)
- 12패 중 마무리 형태: 4-3 7판, 3-3 1판, VCF/막지 못한 4 4판. 흑 6패·백 6패.
- 12판 모두 "보스 수 직후 상대 필승" 지점 **이전에 이미** 상대가 필승이었음 → 진짜 실착은 그보다 앞의 **조용한 준비 수**(4도 열린3도 아닌 수)를 못 본 것. VCT는 4와 열린 3만 따라가서 이걸 못 잡음.
- 보스가 거의 매 수 시간 한도(약 5.25초 = 탐색 3.5초 + VCF 50%)를 다 씀 → 설정 깊이 10은 실제로 도달하지 못함.
- 4-3 방어는 무의미했음: 상대 4-3 자리는 이미 VCT 위협 감지에 걸림. 마무리 모양(4-3)은 원인이 아니라 결과.
- 주의: 필승 판정 탐색 자체가 불완전(같은 수가 1.5초 검사 "안전", 4초 검사 "필패"로 갈린 사례 있음). 분석 지점은 "근처"로 볼 것.

## 다시 측정할 때
1. `node tests/duel-record.js 20 1 games.json` (약 45~60분, 다른 무거운 작업 없이 — 시간 제한 탐색이라 CPU 경합 시 결과 왜곡)
2. `node tests/analyze-losses.js games.json`
3. **수순이 실제로 바뀌었는지 먼저 확인**: 같은 시드에서 변경 전후 기보가 똑같으면 그 변경은 효과 없음.
4. AI끼리 대국에서는 학습(회전 기억 등) 효과가 측정되지 않음 — 학습은 사람과 둬야 확인 가능.
