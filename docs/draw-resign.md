# 무승부·항복 (설계)

지금은 판이 다 차야 무승부다(`app.js` `showDrawOverlay` 호출부, `room.js` `board.flat().every(...)`). 이길 길이 없는데도 무승부를 보려고 빈칸을 채워야 한다. 세 가지를 넣는다.

## 1. 둘 곳 없음 알림 ("더 이상 둘 수가 없습니다")

- 5칸 줄(가로·세로·두 대각선)마다, 상대 돌이 하나도 없으면 그 줄은 그 사람에게 "열린 줄"이다.
- 흑·백 모두 열린 줄이 하나도 없으면 아무도 5목을 만들 수 없다. **게임을 끝내지 않고 알리기만 한다**(2026-11-25 사용자 결정).
- 5목에는 상대 돌이 없는 5칸 줄이 반드시 필요하다. 그래서 이길 수 있는 판에 이 알림이 뜨는 일은 없다(흑 금수까지 따지면 더 일찍 막힐 수 있지만 v1은 무시).
- 표시: 판 아래 상태 줄에 **"더 이상 둘 수가 없습니다"**를 띄우고, "무승부 제안" 버튼을 강조한다(포인트 색 채움 + 은은한 깜빡임, `prefers-reduced-motion`이면 깜빡임 없음). 판이 다 차면 지금처럼 무승부로 끝난다.
- 순수 함수 하나로 처리한다: `TeamLogic.bestWindow(board, p)` = 열린 줄 중 `p` 돌이 가장 많이 든 줄의 돌 수, 열린 줄이 없으면 `-1`. 둘 곳 없음 = `bestWindow(b,1) < 0 && bestWindow(b,2) < 0`. 수를 둘 때마다 확인한다(AI 대전은 app.js, 방은 각자 snap의 board로 계산 — 메시지 추가 없음).

## 2. 무승부 제안

- "무승부 제안"·"항복" 버튼은 **늘 보인다**(내 차례가 아닐 때, 게임 전·후에도, 2026-11-25 사용자 결정). 쓸 수 없으면 비활성(흐리게)이고 `title`에 이유를 쓴다: 게임 중이 아님 "진행 중인 게임이 없습니다", 투표 중 "투표가 진행 중입니다", AI 생각 중 "AI가 생각 중입니다", 무승부는 내(팀) 차례가 아님 "내 차례에 제안할 수 있습니다", 횟수를 다 씀 "이번 판의 무승부 제안 기회를 모두 썼습니다".
- 무승부 제안은 자기(팀) 차례에만(방은 방장도 검사). 평소에도 보조 버튼보다 눈에 띄게(포인트 색 테두리) 두고, 둘 곳 없음 상태에서는 위처럼 강조한다. 시계는 멈추지 않는다.
- **AI 대전**: AI는 `bestWindow(board, AI색) <= 2`(3개 이상 든 열린 줄이 없음)이면 받고, 아니면 거절한다(알림 "AI가 무승부를 거절했습니다 — 게임이 계속됩니다!", 4초 뒤 사라짐). 보스도 같은 규칙. `ai.js`는 건드리지 않는다(동기화 규칙).
- **방 (팀전)**: 무승부는 **방의 모든 플레이어가 동의**해야 한다(2026-11-25 사용자 결정).
  1. 한 사람이 제안하면 제안자를 뺀 접속 중인 모든 플레이어(우리 팀·상대 팀)에게 **동시에** 묻는다(2026-11-25 사용자 결정). 전원이 동의해야 무승부다. 상대가 받지 않으면 무승부는 성립하지 않는다.
  2. 한 명이라도 거절하거나 20초 안에 답이 없으면 취소된다. 취소 이유는 모두에게 알린다(아래 §4 `why`).
  3. 투표 대상은 그 순간 접속 중인 플레이어다. 접속이 끊긴 사람은 빼고, 투표 중에 끊기면 그 사람도 뺀다.
- 한 사람은 한 판에 무승부 제안을 **2번**까지 할 수 있다(도배 방지, AI 대전·방 공통). 다 쓰면 버튼은 그대로 보이고 비활성된다.

## 3. 항복

- "항복" 버튼 → 확인 창("정말 항복할까요?") → 즉시 패배.
- AI 대전: 사람이 지고 AI가 이긴 것으로 학습 기록(`GomokuAI.learn`)에 남긴다.
- 방 (팀전): 항복은 **자기 팀 전원이 동의**해야 한다. 같은 팀 접속자에게 묻고, 모두 동의하면 패배, 한 명이라도 거절하거나 20초가 지나면 취소. 혼자 남은 팀이면 확인 창만 거친다. **항복은 횟수 제한이 없다**(2026-11-25 사용자 결정, ZESTMOK과 같음).

## 4. 방 프로토콜 (room-dev)

무승부와 항복은 같은 투표 흐름 하나로 처리한다(`kind: 'draw' | 'resign'`).

| 방향 | 메시지 | 방장 처리 |
| --- | --- | --- |
| G→H | `{type:'vote-start', kind}` | 게임 진행 중, 진행 중인 투표 없음. 무승부는 보낸 사람 팀 차례 + 제안 횟수 남음일 때만, 접속한 상대가 없으면 거절 `why:'nofoe'`(제안자에게만) |
| H→G | `{type:'vote', kind, from, ask:[id...], yes:[id...], ends}` | `yes`: 동의한 사람(제안자 포함), `ask`: 아직 답하지 않은 접속자, `ends`: 남은 ms. `ask`에 든 사람에게 동의/거절 버튼 |
| G→H | `{type:'vote-reply', ok}` | `ask`에 든 사람만 유효. 거절이면 취소 |
| H→G | `{type:'vote', kind, from, cancelled:true, why, by}` | `why`: `refused`(`by` = 거절한 사람 id) · `timeout` · `left`(투표 중 상대 팀이 모두 나감) · `nofoe` · 없음(다른 이유로 게임 종료) |

- 투표 중에는 방의 모든 플레이어에게 진행 상황 "동의 1/4"를 보여준다. 제안자는 동의한 것으로 센다: 표시 = `yes` 수 / (`yes` 수 + `ask` 수)(2026-11-25 사용자 결정, `yes`에 제안자가 들어 있음). 기존 `vote` 메시지로 갱신하고 새 메시지는 없다.
- `ask`는 답이 오거나 접속이 바뀔 때마다 다시 계산한다(투표 중 다시 들어온 사람도 묻는다). 무승부: 아직 답하지 않은 접속자 전원. 항복: 제안자 팀의 아직 답하지 않은 접속자. `ask`가 비면 결과를 낸다.
- **무승부는 강제될 수 없다**: 상대 팀마다 적어도 한 명이 `yes`에 있어야 성립한다. 상대 팀에 접속자도 동의자도 없으면(시작 때 또는 투표 중 이탈) 투표를 취소한다(리뷰 지적, 2026-11-25).
- 취소되면(`nofoe` 제외, 게임이 계속될 때만) **모든 클라이언트**가 4초 동안 알림을 띄운다: "○○님이 무승부 제안을 거절했습니다 — 게임이 계속됩니다!", "응답이 없어 무승부 제안이 취소되었습니다 — 게임이 계속됩니다!", "참가자가 나가 무승부 제안이 취소되었습니다 — 게임이 계속됩니다!"(항복이면 "항복을/항복이"). `why`가 없으면 알림 없음(게임 종료와 함께 오는 취소). `nofoe`는 제안자 상태 줄에만 짧게.
- 제안 횟수는 무승부만 센다: 2번(snap `offers: {draw:{id:n}}`, 승계 후에도 유지). 항복은 세지 않는다.
- 방장도 플레이어면 자기 답을 같은 함수로 처리한다.
- 결과는 기존 snap의 `result`로 보낸다: 항복 `{winner, reason:'resign'}`, 무승부 `{draw:true, reason:'agreed'}`. `room.js`의 result 정리 코드(`reason` 허용 목록)에 `resign`, `agreed`를 추가한다.
- 투표 순서·인원 계산은 순수 함수로 `team.js`에 두고 단위 테스트한다(`TeamLogic.voteAsk`: 무승부에 상대가 없으면 `null`).

## 5. 담당과 순서

3단계(사진 돌) 병합 후 진행한다. app.js·room.js·team.js가 지금 병렬 작업 중이기 때문이다.
- room-dev: `bestWindow`·투표 순수 함수(team.js, 단위 테스트), 투표 메시지·방장 검증, 방에서 둘 곳 없음 알림
- ui-dev: 버튼 두 개(무승부 제안 강조)·확인 창·투표 창·상태 줄 문구, AI 대전 알림·제안·항복, `tests/ui.e2e.mjs`
