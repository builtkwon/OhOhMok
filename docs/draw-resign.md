# 무승부·항복 (설계)

지금은 판이 다 차야 무승부다(`app.js` `showDrawOverlay` 호출부, `room.js` `board.flat().every(...)`). 이길 길이 없는데도 무승부를 보려고 빈칸을 채워야 한다. 세 가지를 넣는다.

## 1. 자동 무승부 ("더 이상 둘 수가 없습니다")

- 5칸 줄(가로·세로·두 대각선)마다, 상대 돌이 하나도 없으면 그 줄은 그 사람에게 "열린 줄"이다.
- 흑·백 모두 열린 줄이 하나도 없으면 아무도 5목을 만들 수 없다 → 즉시 무승부.
- 5목에는 상대 돌이 없는 5칸 줄이 반드시 필요하다. 그래서 이 판정은 이길 수 있는 판을 무승부로 끊지 않는다(흑 금수까지 따지면 더 일찍 막힐 수 있지만 v1은 무시).
- 표시: 판 아래 상태 줄에 **"더 이상 둘 수가 없습니다"**, 결과 창 제목은 "무승부!".
- 순수 함수 하나로 처리한다: `TeamLogic.bestWindow(board, p)` = 열린 줄 중 `p` 돌이 가장 많이 든 줄의 돌 수, 열린 줄이 없으면 `-1`. 무승부 = `bestWindow(b,1) < 0 && bestWindow(b,2) < 0`. 수를 둘 때마다(AI 대전은 app.js, 방은 방장 room.js) 확인한다. 판이 다 찬 경우도 여기에 포함된다.

## 2. 무승부 제안

- 자기 차례에 "무승부 제안" 버튼. 시계는 멈추지 않는다.
- **AI 대전**: AI는 `bestWindow(board, AI색) <= 2`(3개 이상 든 열린 줄이 없음)이면 받고, 아니면 거절한다. 보스도 같은 규칙. `ai.js`는 건드리지 않는다(동기화 규칙).
- **방**: 제안은 상대 팀에게 간다. 상대 팀 중 한 명이 받으면 무승부, 거절하거나 15초 안에 답이 없으면 취소. 한 사람은 한 판에 제안을 3번까지 할 수 있다(도배 방지).

## 3. 항복

- "항복" 버튼 → 확인 창("정말 항복할까요?") → 즉시 패배.
- AI 대전: 사람이 지고 AI가 이긴 것으로 학습 기록(`GomokuAI.learn`)에 남긴다.
- 방: 팀원 누구나 자기 팀을 대표해 항복할 수 있다.

## 4. 방 프로토콜 (room-dev)

| 방향 | 메시지 | 방장 검증 |
| --- | --- | --- |
| G→H | `{type:'draw-offer'}` | 게임 진행 중, 보낸 사람 팀 차례, 제안 횟수 남음 |
| H→G | `{type:'draw-offer', team}` | 상대 팀에게 버튼 표시 |
| G→H | `{type:'draw-reply', ok}` | 진행 중인 제안이 있고 보낸 사람이 상대 팀 |
| G→H | `{type:'resign'}` | 게임 진행 중, 보낸 사람이 플레이어 |

- 결과는 기존 snap의 `result`로 보낸다: 항복 `{winner, reason:'resign'}`, 무승부 `{draw:true, reason:'agreed'|'dead'}`. `room.js`의 result 정리 코드(`reason` 허용 목록)에 `resign`, `agreed`, `dead`를 추가한다.

## 5. 담당과 순서

3단계(사진 돌) 병합 후 진행한다. app.js·room.js·team.js가 지금 병렬 작업 중이기 때문이다.
- room-dev: `bestWindow`(team.js, 단위 테스트), 방 메시지·방장 검증, 방 자동 무승부
- ui-dev: 버튼 두 개·확인 창·상태 줄 문구, AI 대전 자동 무승부·제안·항복, `tests/ui.e2e.mjs`
